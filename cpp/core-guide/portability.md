# C++ 核心指南：可移植性与兼容性

## 可移植性（Portability）

- **避免依赖平台特定特性**  
  不要依赖于特定操作系统、编译器或硬件的特性。优先使用标准 C++ 语言和标准库，避免使用特定平台的 API 或汇编指令。

- **使用标准类型和库**  
  使用如 `std::int32_t`、`std::size_t` 等标准类型，避免使用平台相关的基本类型（如 `long`、`int` 的长度在不同平台可能不同）。优先使用标准库（如 STL、标准算法、智能指针等）。

- **避免未定义和实现定义行为**  
  避免使用 C++ 标准未定义或实现定义的行为，如对象的内存布局、字节序、指针与整数的转换、未初始化变量等。

- **处理字符集和本地化问题**  
  注意不同平台的字符编码和本地化差异，优先使用 UTF-8 和标准库的本地化支持。避免假设 `char` 总是 ASCII，处理多语言和多区域设置时使用 `std::locale`。

- **使用可移植的构建系统**  
  采用 CMake 等跨平台构建工具，避免依赖特定平台的构建脚本。保持构建脚本简洁，避免硬编码路径和平台相关参数。

- **关注文件路径和换行符差异**  
  处理文件路径时，使用标准库（如 `<filesystem>`）避免手动拼接路径分隔符。处理文本文件时注意不同平台的换行符（`\n` vs `\r\n`）。

- **测试多平台兼容性**  
  在不同操作系统、编译器和硬件架构上进行测试，及时发现和修复平台相关问题。

## 兼容性（Compatibility）

- **保持向后兼容性**  
  在修改库或接口时，尽量保持与旧版本的兼容，避免破坏已有用户的代码。对于必要的破坏性变更，提供兼容层或迁移工具。

- **明确 API 变更**  
  对外暴露的接口变更要有清晰的文档说明，并提供迁移指南。采用语义化版本控制（Semantic Versioning）标识变更类型。

- **使用特性检测而非版本检测**  
  检查编译器或库是否支持某特性时，优先使用特性检测（如 `#ifdef __cpp_if_constexpr`），而不是仅检测版本号。这样能更好地适应不同编译器和标准库实现。

- **避免依赖未标准化扩展**  
  不要依赖编译器或平台的非标准扩展，以保证代码能在不同环境下编译和运行。必要时使用条件编译，并提供标准实现的替代方案。

- **兼容不同标准版本**  
  尽量支持主流 C++ 标准（如 C++11、C++14、C++17、C++20），并在文档中注明最低支持的标准版本。

- **处理 ABI 兼容性**  
  关注不同编译器、不同标准库实现之间的 ABI 差异，避免暴露易变的 ABI（如直接暴露 STL 容器）。

- **提供单元测试和回归测试**  
  通过自动化测试保证新版本对旧功能的兼容性，及时发现兼容性回归问题。
