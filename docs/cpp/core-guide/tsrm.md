# 类型安全与资源管理

## 类型安全

- **避免类型转换错误**  
  尽量避免使用 C 风格强制类型转换，优先使用 `static_cast`、`dynamic_cast`、`const_cast`、`reinterpret_cast` 等 C++ 类型安全的转换方式。这样可以提升代码的可读性和安全性，减少因类型转换导致的潜在错误。

- **使用强类型枚举**  
  推荐使用 `enum class` 替代传统的 `enum`，防止隐式转换和作用域污染。`enum class` 提供更严格的类型检查，避免不同枚举类型之间的混用。

- **避免隐式类型转换**  
  明确禁止不安全的隐式类型转换。构造函数应加 `explicit` 关键字，防止单参数构造函数被隐式调用，减少意外的类型转换。

- **利用类型系统表达约束**  
  充分利用类型系统表达对象的状态和约束，如使用自定义类型、模板、constexpr 等，减少运行时错误，将更多问题暴露在编译期。

- **类型别名与静态断言**  
  合理使用 `using` 或 `typedef` 定义类型别名，提升代码可读性。结合 `static_assert` 在编译期校验类型约束，防止类型误用。

## 资源管理

- **RAII（资源获取即初始化）**  
  推荐使用 RAII 原则，将资源的获取和释放绑定到对象的生命周期。通过构造函数获取资源，析构函数自动释放，确保资源始终被正确管理。

- **智能指针**  
  优先使用 `std::unique_ptr`、`std::shared_ptr`、`std::weak_ptr` 管理动态资源，避免裸指针和手动 `new/delete`。智能指针能自动管理资源释放，降低内存泄漏风险。

- **避免资源泄漏**  
  禁止手动管理内存、文件句柄等资源，优先使用标准库容器和资源管理类。通过标准库的自动管理机制，减少资源泄漏和悬挂指针等问题。

- **禁止裸指针转移所有权**  
  不要通过裸指针传递资源所有权，使用智能指针明确所有权关系。这样可以清晰表达资源的生命周期和归属，避免所有权混乱导致的错误。

- **析构函数中释放资源**  
  保证所有资源在析构函数中正确释放，防止内存泄漏和资源泄漏。对于需要手动管理的资源，务必在析构函数中释放，并遵循异常安全原则。

- **资源管理类和容器**  
  优先使用标准库的资源管理类（如 `std::vector`、`std::string`、`std::fstream` 等）和容器，避免直接操作底层资源，提升代码健壮性和可维护性。

- **异常安全**  
  设计资源管理代码时，确保在异常情况下资源也能被正确释放，避免因异常导致的资源泄漏。
