# 库和工具的使用

## 使用库的建议

- **优先使用标准库**  
  优先使用 C++ 标准库（如 `<vector>`, `<string>`, `<algorithm>` 等），它们经过广泛测试、性能优良且可移植性好，能有效减少 bug 和维护成本。

- **避免重复造轮子**  
  在已有高质量库可用时，不要重复实现已有功能。应充分利用 Boost、fmt、Eigen、spdlog 等社区公认的库，提高开发效率和代码质量。

- **选择活跃维护的库**  
  选择有良好文档、活跃社区和持续维护的库，避免使用已废弃或无人维护的库。这样可以获得及时的 bug 修复和新特性支持，降低维护风险。

- **明确库的许可证**  
  在项目中引入第三方库时，确保其许可证与项目兼容，避免法律风险。建议优先选择 MIT、BSD、Apache-2.0 等宽松许可证的库，并在文档中注明依赖库及其许可证。

- **封装第三方库依赖**  
  通过适配器或包装类封装第三方库，减少对外部接口的直接依赖，便于将来替换或升级。这样可以降低耦合度，提高代码的可维护性和可扩展性。

- **关注库的性能和安全性**  
  在引入第三方库时，关注其性能表现和安全性，避免引入已知漏洞或性能瓶颈。可结合静态分析工具和安全公告进行评估。

## 工具的使用建议

- **使用现代编译器和工具链**  
  使用支持 C++17/20/23 的现代编译器（如 MSVC、GCC、Clang），并及时更新。新版本编译器通常带来更好的优化、更严格的检查和新特性支持。

- **集成静态分析工具**  
  利用静态分析工具（如 clang-tidy、Cppcheck、PVS-Studio）自动检测潜在缺陷和代码风格问题，提升代码质量。可将静态分析集成到 CI 流程中，确保每次提交都经过检查。

- **使用包管理工具**  
  推荐使用 vcpkg、Conan、Hunter 等包管理工具统一管理依赖库，简化构建流程，提升可复现性。包管理工具还能自动处理依赖关系和版本兼容问题。

- **持续集成与自动化测试**  
  配置 CI 工具（如 GitHub Actions、Azure Pipelines）自动构建、测试和分析代码质量，确保每次提交都能通过编译和测试，及时发现问题。

- **利用 IDE 和调试工具**  
  充分利用 Visual Studio、CLion、VS Code 等 IDE 的代码补全、重构、调试和性能分析功能，提高开发效率。善用断点、内存分析、性能分析等工具定位和优化问题。

- **自动化文档和代码格式化**  
  集成 Doxygen、Sphinx 等自动化文档工具，保持文档与代码同步。使用 clang-format、astyle 等代码格式化工具统一代码风格，提升可读性。

- **定期更新工具链和依赖**  
  定期检查并升级编译器、工具链和第三方库，及时获取安全补丁和新特性，避免因版本过旧导致的兼容性和安全问题。
