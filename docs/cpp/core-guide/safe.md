# 安全性

## 基本原则

- **优先使用安全的库和语言特性**  
  使用标准库（如 `std::vector`、`std::string`、`std::array`）代替裸指针和手动内存管理，减少悬垂指针和内存泄漏风险。优先使用范围 for 循环、智能指针等现代 C++ 特性。

- **避免未定义行为**  
  遵循 C++ 标准，避免越界访问、空指针解引用、未初始化变量、数据竞争等未定义行为。使用标准库算法和容器，减少手动操作原始内存。

- **限制资源的所有权和生命周期**  
  使用智能指针（如 `std::unique_ptr`、`std::shared_ptr`、`std::weak_ptr`）管理资源，明确资源的所有权和生命周期，防止资源泄漏和重复释放。

- **防止缓冲区溢出**  
  避免使用不安全的 C 风格字符串和数组操作（如 `strcpy`、`sprintf`、`gets`），优先使用 `std::string`、`std::vector` 及其安全成员函数。对数组访问进行边界检查。

- **输入校验和边界检查**  
  对所有外部输入进行校验，确保数据在合理范围内，防止注入和溢出攻击。对用户输入、文件、网络数据等进行严格验证。

- **最小权限原则**  
  只授予代码所需的最小权限，避免不必要的全局变量和可变状态。限制类和函数的可见性，使用 `private`、`protected`、`const`、`constexpr` 等关键字。

- **使用 RAII 管理资源**  
  利用构造函数和析构函数自动管理资源（如文件、互斥锁、内存等），防止资源泄漏。优先使用标准库的 RAII 类型（如 `std::lock_guard`、`std::unique_lock`）。

- **启用编译器警告和静态分析工具**  
  打开所有编译器警告（如 `/W4`、`-Wall -Wextra`），并使用静态分析工具（如 clang-tidy、Cppcheck、Visual Studio 静态分析）检测潜在安全问题。定期审查和修复警告。

- **避免类型转换错误**  
  避免不安全的类型转换，优先使用 `static_cast`、`dynamic_cast`、`const_cast`、`reinterpret_cast` 明确表达意图。避免隐式类型转换带来的安全隐患。

- **多线程安全**  
  在多线程环境下，使用线程安全的容器和同步机制（如 `std::mutex`、`std::atomic`），避免数据竞争和死锁。

- **及时修复已知漏洞**  
  关注第三方库和依赖的安全公告，及时更新和修复已知安全漏洞。
