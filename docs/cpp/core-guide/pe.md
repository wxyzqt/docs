# 性能与效率

## 避免不必要的拷贝

- 优先使用引用（const&）或指针传递大型对象，减少拷贝开销。
- 对于需要转移资源所有权的场景，利用移动语义（std::move）提升性能。

## 选择合适的数据结构

- 根据实际需求选择最合适的标准库容器（如 std::vector、std::map、std::unordered_map），避免滥用低效容器。
- 优先使用 std::vector，其内存布局和访问效率通常优于其他容器。
- 对于频繁插入/删除的场景，可考虑 std::list 或 std::deque。
- 避免在不需要排序或唯一性的场景下使用 std::set、std::map。

## 避免不必要的动态分配

- 尽量减少 new 和 delete 的使用，优先使用栈对象和标准容器自动管理内存。
- 对于需要频繁创建和销毁对象的场景，使用对象池等技术复用资源，减少分配和释放带来的性能损耗。

## 利用算法库

- 优先使用标准库算法（如 std::sort、std::find），避免手写低效循环。
- 标准算法经过高度优化，通常比手写代码更高效，也更易读。

## 局部性原则

- 优化数据结构和访问模式，提升缓存命中率，减少内存访问延迟。
- 连续存储的数据结构（如 std::vector）有助于提升局部性。
- 尽量避免频繁的随机访问和跨页访问。

## 延迟计算与懒加载

- 仅在需要时才进行计算或加载资源，避免不必要的性能消耗。
- 可采用惰性初始化（Lazy Initialization）或缓存（Cache）机制，提升整体效率。

## 避免虚函数滥用

- 虚函数有一定的运行时开销，性能敏感场景下可考虑去虚化或使用模板实现多态。
- 对于频繁调用的接口或小型函数，优先考虑非虚函数或 CRTP（Curiously Recurring Template Pattern）等模板技术。

## 其他建议

- 避免频繁的系统调用，如文件操作、线程切换等，尽量批量处理或异步处理。
- 合理使用并发，多线程/多进程可提升性能，但需注意同步开销和资源竞争。
- 定期使用性能分析工具定位瓶颈，针对性优化。
- 合理设置编译器优化参数，开启高级优化选项。
