# utf-16

2 或 4 字节宽字符编码，主要用于内存处理(编程语言内部字符串存储)

基本多语言平面：U+0000 - U+FFFF，用 2 字节表示

辅助平面(16 个)：U+10000 - U+10FFFF，需要代理对，即 4 字节表示

## 代理对

最早期 uft-16 只支持 2 字节，即定长 16 位，这一特性让其字符处理速度远超 utf-8

Unicode3.0 引入了代理对，扩展了字符表示范围

这一扩展导致 uft-16 的速度被牺牲，且部分情况下需要对 4 字节的字符特殊处理

## 代理区

代理区为 U+D800 - U+DFFF

代理区分为高位代理(0xD800-0xDBFF)和低位代理(0xDC00-0xDFFF)

假设 X 为字符的码点，则代理对的计算公式为:

`高位代理：(X - 0x10000) / 0x400 + 0xD800`

`低位代理：(X - 0x10000) % 0x400 + 0xDC00`

## BOM

Byte Order Mark,节序标记，Unicode 中的特殊字符(U+FEFF)

U+FEFF，Zero Width No-Break Space(零宽无间断间隔)

该字符在文件头部不可见，但通过二进制可检测其字节序列。

U+FEFF 最初为排版控制符，后因 utf-16/32 的字节序需求被赋予 BOM 功能

Unicode3.2 后，排版用途由 U+2060 替代，U+FEFF 专用于文件头部标记。

### 具体表现

- UTF-8‌：BOM 为 EF BB BF(3 字节)
- UTF-16‌：
  - 大端序(BE)：FE FF
  - 小端序(LE)：FF FE‌
- ‌UTF-32‌：
  - 大端序：00 00 FE FF
  - 小端序：FF FE 00 00‌

utf-8 的 BOM 非必须，windows 部分程序(记事本、Visual Studio)可能添加。

现在推荐更广泛的无 BOM，utf-8 编码编写文件。
