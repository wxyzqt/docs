# 配置文件

这里仅指用于软件环境及编程的配置文件。

经过多年发展淘汰，目前广泛引用的配置文件大致分为三种用途。

## 传输

以 [json](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/JSON) 为代表：

- 优点：信息结构化、简要、体积小、便于传输
- 缺点：不能添加注释信息

这种文件格式主要用于网络传送。

虽然有 json5 可以添加注释，但并不算通用，因为其违背了传输的简要原则。

## 编程控制

各门编程语言，内含了其语言后缀的配置文件。

以 javascript 为例，其配置文件通常形式为`config.js`。

- 优点：语言内置，直接引用解析，可以添加注释
- 缺点：跨语言合作体验不佳

这种文件格式主要用于编程控制。

## 跨语言环境

[yaml](https://www.runoob.com/w3cnote/yaml-intro.html) 格式的配置文件，因其结构简要，可以添加注释，成为跨语言跨平台的主流配置文件格式。

- 优点：跨环境，便于多人合作，可以添加注释
- 缺点：简单编程环境中体验不如语言内置；网络传输速度不如 json。

这种文件格式主要用于非以上两种情况。
