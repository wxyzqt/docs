# x86

[cpu 架构](../../assembly/framework-order-compiler)有多种选择，本仓库采用 x86，原因有二：x86 架构在 linux 和 windows 都有良好实现；学习资料相对容易查找。

相应的，x86 采用复杂指令集(CISC)，我们使用[nasm](../../assembly/nasm) 的汇编语法。

## 先看最后目标

如果已经完成[开发环境](../env/devenv)配置，终端里能成功访问到各命令。

不妨在 os 仓库的根目录运行`make`命令，如果成功生成 build 文件夹，再运行`make bochs`或者`make qemu`。

最后能看到一个窗口，在等待文字输入，恭喜你，很顺利的运行了一份极简版操作系统。

:::tip
如果没有生成 build 目录也无所谓，随着学习，知识累积之后，中间出现的问题自然会被解决。
:::

## 仓库目录介绍

简单介绍下 os 仓库下各目录:

- boot 引导程序相关汇编代码
- build 生成的目标文件目录
- cpu 与 CPU 架构相关的底层代码，在复杂项目中通常使用 arch/x86、arch/arm 结构，arch 即 architecture‌(架构)的缩写
- drivers 驱动程序相关代码
- example 配套 docs 仓库代码分析的示例，与 os 仓库代码无关
- kernel 内核入口和主控制循环
- libc 自写开发的库，这里是尊重原仓库，其实应当为 rt(runtime library
  )，即运行时库
- setup 随仓库的 windows 开发环境安装包
- bochsrc bochs 配置文件，使用 bochs 时才需要
- Makefile 编译配置文件

## 从 bios 启动

首先要明确的一点：BIOS 是主板自带的固件程序。

也就是说 bios 并非由操作系统书写，而是集成在主板的 ROM 芯片中，出厂即带。

主机电源接通，第一个运行的固件就是 bios 程序，经过硬件状态自检后，将磁盘 0 柱面 0 磁道 1 扇区的 512 字节内容加载到内存地址 0x7c00。

首个物理扇区(512 字节)的引导代码就是 MBR(主引导记录)。

### UEFI

Unified Extensible Firmware Interface,统一可扩展固件接口。是现代固件标准，支持 GPT 分区表，提供了图形化界面和更快的启动速度。

:::tip
UEFI 是 BIOS 的替代者，可以认为是 bios 的升级版。其兼容模式也提供了 Legacy BIOS 启动。

但是学习操作系统，首先接触 bios 更直观。
:::

:::info 扩展
电源开机，按 F12 或者其他键(不同厂商按键不一致)，进入的设置界面，如果是图形化的，就是 uefi 启动。
最常见的就是网吧里通过 uefi 选择操作系统。
:::
