# 文件目录

kernel_main 这个命名主要是为了避免与标准库或编译器中的 main 函数发生冲突。

在操作系统内核开发中：

标准 C 运行时环境期望有一个 main 函数作为程序入口
但内核在启动初期已经接管了系统控制权，绕过了标准 C 库的初始化
使用 kernel_main 可以明确标识这是内核特有的入口点，避免链接器混淆
同时也能在代码中清晰区分内核代码和用户空间应用程序代码

这些宏定义用于 ‌ 中断向量号的重映射 ‌，是 x86 架构中可编程中断控制器(PIC)初始化的一部分。

用途说明：‌

在 x86 系统中，主 PIC 默认使用中断向量 0-7，从 PIC 使用 8-15。这与 CPU 的异常向量（0-31）冲突，比如 IRQ0（定时器中断）会覆盖除法错误异常。

通过将 IRQ0-15 重新映射到 32-47：

避免冲突 ‌：将硬件中断与 CPU 异常的中断向量号分开
系统兼容 ‌：为 32 个 CPU 异常保留 0-31 号向量
统一管理 ‌：为所有硬件中断分配连续的向量号空间
这是操作系统内核初始化 PIC 的标准操作，确保中断处理系统能够正确区分各种中断源。

## 何时使用 c 标准库

判断 C 语言标准库是否独立于运行时环境，主要看它是否需要底层系统支持或动态内存管理
在操作系统开发中，C 语言 ‌ 在完成基本的运行时环境初始化后 ‌ 就可以使用标准库了。具体来说，需要先实现以下几个关键步骤：

核心前提条件
内存管理就绪 ‌

实现 malloc()/free()等动态内存分配函数
建立堆空间管理机制，为库函数提供内存支持
系统调用封装 ‌

将内核的系统调用封装成 C 库可识别的接口
例如实现\_write()、\_read()等底层 I/O 函数
启动代码完善 ‌

完成\_start 等入口函数的初始化工作
设置好栈指针、全局变量初始化等环境
标准库的分阶段使用
早期阶段可用 ‌：

<stddef.h>、<stdint.h>：类型定义
<string.h>：内存操作、字符串处理
<ctype.h>：字符类型判断
环境完善后可用 ‌：

<stdio.h>：文件操作、格式化输出（需文件系统支持）
<stdlib.h>：动态内存管理、环境变量
<math.h>：数学运算（需浮点单元支持）

低 8 位：CH 寄存器
高 2 位：CL 寄存器的高 2 位（第 6-7 位）
盘面号(Head)‌：DH 寄存器（取值范围 0x0 到 0xF，即 0-15）

扇区号(Sector)‌：CL 寄存器的低 6 位（第 0-5 位）

具体示例：‌
如果要读取柱面 5、盘面 2、扇区 3：

CH = 5（柱面号低 8 位）
CL = (5 >> 8) << 6 | 3
DH = 2
